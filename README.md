# NexusEd AI

**Turn any document into a mind map you can learn from.**

Upload a PDF, Word (.docx) or PowerPoint (.pptx) file. NexusEd AI reads it, finds the
key concepts and draws an interactive mind map. Click any concept to get a simple
explanation, a real-life example, three key points, a one-question quiz and the exact
pages or slides it came from. Everything runs **locally and offline**: no paid APIs and
no cloud.

```
Browser (HTML + Tailwind + Cytoscape.js)
   │  upload / poll / click
   ▼
FastAPI app ──► parser (pypdf, python-docx, python-pptx) ──► chunks
   │            embeddings (all-MiniLM-L6-v2) ──► Qdrant (vector DB)
   │            YAKE keywords ──► Ollama LLM ──► mind map
   │            click: Qdrant top 20 ──► cross-encoder rerank top 4 ──► Ollama ──► explanation
   ▼
SQLite (documents, mind maps, explanation cache)
```

---

## Prerequisites

1. **Docker Desktop**: <https://www.docker.com/products/docker-desktop/> (start it once so the whale icon is running).
2. **Ollama**: <https://ollama.com/download>, running on your machine (not in Docker).
3. Pull the language model (about 4.9 GB, one time only):
   ```bash
   ollama pull llama3.1:8b
   ```
   On a low-RAM laptop you can use the smaller `llama3.2:3b` instead. Set `LLM_MODEL=llama3.2:3b` in `.env`.

## Run with Docker (recommended for the demo)

```bash
cd nexus-ed-ai
cp .env.example .env          # first time only
docker compose up -d --build  # first build takes ~5–10 min (downloads PyTorch + models)
```

Open <http://localhost:8000>. Both chips in the top-right should be green.

Stop it with `docker compose down`. Your uploads stay in `./data` and vectors in `./qdrant_storage`.

## Run in dev mode (code reloads on save)

Only Qdrant runs in Docker; the app runs on your laptop.

```bash
cd nexus-ed-ai
docker compose up -d qdrant

python3 -m venv .venv
source .venv/bin/activate
pip install torch==2.15.0 --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt

OLLAMA_URL=http://localhost:11434 QDRANT_URL=http://localhost:6333 \
  uvicorn app.main:app --reload
```

The first start downloads the two small sentence-transformers models (~110 MB) from Hugging Face.

## Run the tests

```bash
source .venv/bin/activate
pytest
```

The tests need neither Docker nor Ollama: Qdrant runs in memory and the LLM is faked or deliberately unreachable.

## Try it end to end

1. Open <http://localhost:8000> and drop a `.pdf`, `.docx` or `.pptx` on the upload zone.
2. Watch the four steps tick off (reading → understanding → concepts → mind map).
3. The mind map appears. Hover a concept to highlight its branch, then click it.
4. The side drawer shows the explanation, example, key points, quiz and source chips.
   Answer the quiz, flip **Explain simpler**, and watch the "N of M explored" bar fill up.
5. Use **Fit**, **Re-layout**, **PNG** (export) and **New** in the top bar. **Esc** closes the drawer.

API docs (auto-generated by FastAPI): <http://localhost:8000/docs>

## Configuration (`.env`)

| Variable | Default | Meaning |
|---|---|---|
| `OLLAMA_URL` | `http://host.docker.internal:11434` | Where Ollama runs (`http://localhost:11434` in dev mode) |
| `LLM_MODEL` | `llama3.1:8b` | Any model you've pulled with `ollama pull` |
| `LLM_NUM_CTX` | `8192` | Context window given to the model |
| `LLM_TIMEOUT` | `180` | Seconds to wait for one LLM answer |
| `QDRANT_URL` | `http://qdrant:6333` | `http://localhost:6333` in dev mode |
| `QDRANT_COLLECTION` | `nexus_chunks` | Collection name |
| `EMBED_MODEL` / `RERANK_MODEL` | MiniLM models | Hugging Face model names |
| `DATA_DIR` | `./data` | Uploads + SQLite database |
| `MAX_UPLOAD_MB` | `25` | Upload size limit |

## Linux note

Ollama listens only on `127.0.0.1` by default, which containers can't reach. Make it listen on all interfaces:

```bash
sudo systemctl edit ollama    # add the two lines below, save, then:
# [Service]
# Environment="OLLAMA_HOST=0.0.0.0"
sudo systemctl restart ollama
```

`docker-compose.yml` already maps `host.docker.internal` to the host with `extra_hosts`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| **Ollama chip red** | Start Ollama (open the app, or `ollama serve`). On Linux see the note above. |
| **Ollama chip amber** | Model missing: `ollama pull llama3.1:8b` (or set `LLM_MODEL` to a model you have: `ollama list`). |
| **Qdrant chip red** | `docker compose up -d qdrant`, then check `docker compose logs qdrant`. |
| **"No readable text found. Is this a scanned PDF?"** | The PDF is images only. Use a text-based PDF (OCR isn't included). |
| **Map says "built from headings and keywords"** | The LLM failed or was down, so the no-AI fallback map was used. Fix Ollama, then delete the document and re-upload. |
| **Explanations are slow** | First answer per concept takes 5–30 s on a laptop; repeat clicks are instant (cached). A smaller model (`llama3.2:3b`) is faster. |
| **Port 8000 already in use** | Stop the other program, or change `"8000:8000"` to e.g. `"8080:8000"` in `docker-compose.yml`. |
| **Page loads without styling or graph** | Tailwind, Cytoscape and the Inter font load from CDNs, so the browser needs internet once (it caches them afterwards). |
| **Want a clean slate** | `docker compose down && rm -rf data qdrant_storage` |
